# Architecture Decision Records

Create one ADR for any durable choice that changes routing, navigation, component boundaries, data handling, clinical behavior, external dependencies, integration contracts, or repository-wide quality gates.

Use `NNNN-short-kebab-title.md`. Each ADR must state status, date, context, decision, evidence, alternatives considered, consequences, and implementation/validation links. Agents must read relevant accepted ADRs before proposing conflicting work. See `../GOVERNANCE.md` for the full decision policy.
